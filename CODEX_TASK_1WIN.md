# Техническое задание для Codex: парсинг и адаптация шаблона 1Win

## 0. Роль и цель

Ты — senior frontend/full-stack engineer. Реализуй автономный проект, который:

1. Сохраняет **полную неизменённую копию** доступного исходного сайта `https://casino-1win-ar.com/` (исходный шаблон для передачи заказчику).
2. На основании скопированного шаблона формирует **отдельную очищенную версию** сайта только с тремя страницами.
3. Наполняет эти страницы **предоставленным заказчиком уникальным англоязычным контентом**, не переписывая и не выдумывая тексты.
4. Настраивает сайт для домена `https://1-win.co.tz/`, локали `en-TZ` и промокода `GOL5`.
5. Передаёт воспроизводимые скрипты, готовый сайт, исходный шаблон и отчёт о проверке.

**Важно:** не ограничивайся планом или описанием. Реализуй код, запусти сборку, проверь результат. Если выполнение блокируется недоступностью сайта, редиректом на другой домен, ограничениями доступа к Google Drive или правами на материалы, честно зафиксируй проблему в `REPORT.md` и не подменяй источник другим сайтом без явного подтверждения.

Если Codex не имеет доступа к Google Drive, предусматривай локальную поставку входных файлов в `input/content/` (DOCX + `Pics/`), опиши требуемую раскладку и выдай конкретный список отсутствующих файлов. Не заменяй документы самостоятельно сгенерированным текстом.

## 2. Предварительное исследование (обязательно)

Прежде чем писать парсер:

1. Проверь HTTP-ответы, цепочки редиректов, итоговый URL, Content-Type, доступность HTML и ресурсов.
2. Если `casino-1win-ar.com` переадресует на сторонний домен, **не скачивай сторонний сайт автоматически как эквивалент оригинала**. Зафиксируй redirect chain и запроси корректный источник или явное разрешение; сохраняй существующие результаты безопасно.
3. Определи тип сайта: статический HTML / SSR / SPA; проверь, нужны ли для рендеринга JavaScript и Playwright.
4. Проверь `robots.txt`, условия использования и наличие разрешения на копирование шаблона и изображений. Не обходи CAPTCHA, авторизацию, антибот-защиту или ограничения доступа.
5. Составь инвентаризацию страниц, ассетов, ссылок, скриптов, шрифтов, SEO-тегов и критичных интерактивных элементов.
6. Проверь содержимое трёх DOCX, включая таблицы, списки, ссылки и изображения.

Все результаты исследования запиши в `REPORT.md`.

## 3. Архитектура проекта

Предпочтение: **Node.js + TypeScript**. Если сайт статический, сохраняй HTML/CSS/JS без переписывания на React/Vite. Применяй `cheerio` для разбора DOM, `mammoth` (или подходящий DOCX-парсер) для извлечения документа, `Playwright` — только там, где нужен браузерный рендеринг и скриншотные проверки.

Предлагаемая структура:

```text
1win-test/
├── README.md
├── REPORT.md
├── package.json
├── tsconfig.json
├── .gitignore
├── input/
│   └── content/
│       ├── home/      # DOCX и Pics (если загружены локально)
│       ├── bet/
│       └── casino/
├── scripts/
│   ├── scrape.ts      # скачивание исходника

│   ├── clean.ts       # очистка копии шаблона
│   ├── populate.ts    # расстановка текста по страницам
│   ├── validate.ts    # техническая проверка результата
│   └── package.ts     # формирование архивов
├── config/
│   ├── site.ts        # домен, локаль, промокод, страницы

```

Допускается скорректировать структуру, если это мотивировано и отражено в `README.md`. **Никогда не модифицируй `source/original/` во время очистки и наполнения**.

## 4. Скрипт №1 — парсинг и сохранение оригинального шаблона

Реализовать `npm run scrape`:

- Скачивать доступные HTML-страницы **в пределах подтверждённого исходного хоста**, стили, скрипты, изображения, SVG, favicon, локальные шрифты и другие необходимые ресурсы.
- Сохранять структуру путей и все страницы оригинала, даже если в итоговой версии нужны только три.
- По возможности сохранять оригинальный HTML и отдельный `manifest.json` со списком URL, локальных файлов, HTTP-статусов, редиректов и ошибок.
- Не собирать внешние сайты/домены рекурсивно; ресурсы сторонних сервисов скачивать только при наличии разрешения и технической необходимости.
- Ограничивать параллелизм и частоту запросов; предусмотреть таймауты и повторные попытки для временных ошибок.
- Не выполнять опасные внешние скрипты и не переносить трекеры/виджеты в готовый сайт без необходимости.
- Добиться максимально близкого визуального воспроизведения исходника без подмены отсутствующих файлов.
- Уметь повторно запускаться без порчи ранее сохранённых файлов.

По завершении сформировать `original-template.zip` **из `source/original/`**, без очистки и замены текстов.

## 5. Скрипт №2 — подготовка итогового сайта

Реализовать отдельные воспроизводимые команды:

- `npm run extract` — разбор трёх DOCX и подготовка структурированных данных;
- `npm run clean` — удаление ненужного из рабочей копии шаблона;
- `npm run populate` — внедрение уникального текста и изображений;
- `npm run build` — полный цикл `extract → clean → populate → validate`;
- `npm run validate` — независимая проверка результата.

### 5.1. Очистка

Для итоговой версии:

- Оставить **только три маршрута**: `/`, `/bet/`, `/casino/` (если содержание документов не указывает на необходимость иных согласованных slug).
- Удалить ссылки и элементы переключения на другие языки: language switcher, альтернативные локали, неподходящие `hreflang` и соответствующие меню.
- Удалить внешние **кликабельные ссылки** (`a[href]`, формы/кнопки с переходом и JS-редиректы) на другие домены. Сохранить только локальную навигацию, якоря и необходимые ссылки на страницы своего домена. **Не ломать ресурсы**: CSS, изображения, шрифты и скрипты сначала локализовать, когда это допустимо, а не удалять вслепую.
- Удалить из меню, футера, breadcrumbs, sitemap и иных блоков ссылки на исключённые страницы. При необходимости удалить и связанные блоки без нарушения вёрстки.
- Заменить все **фактические промокоды, относящиеся к предложениям сайта**, на `GOL5`, включая видимый текст, атрибуты, copy-to-clipboard и данные JS. Не делать широкую слепую замену произвольных строк.
- Убрать внешнюю аналитику, рекламные скрипты, affiliate-трекинг и нежелательные редиректы, если они не нужны для отображения.
- Удалить старые canonical/og:url, language variants, sitemap и структурированные данные, если они указывают на исходный домен или исключённые страницы; пересоздать корректные.

### 5.2. Наполнение

- Использовать **только предоставленный контент** из `1Win Главная.docx`, `1Win Bet.docx`, `1Win Casino.docx`.
- Переносить без потери смысла заголовки (`h1`–`h6`), абзацы, таблицы, нумерованные и маркированные списки, выделения и изображения.
- Порядок секций держать максимально близким к документам; визуально вписывать их в блоки исходного шаблона.
- Разметку секций связывать через явный `config/mappings.ts` или предсказуемые `data-*` якоря, **не заменять весь `body` и не пытаться сопоставлять секции только по текстовому совпадению**.
- Если текст в DOCX не имеет точной пары в шаблоне, создать стилистически согласованный HTML-блок на основе существующей дизайн-системы.
- Сохранять качественную семантическую HTML-разметку и адаптивность.
- Для изображений из `Pics` предусмотреть контролируемое сопоставление и локальные пути; задать `alt` по смыслу изображения (без выдуманных фактов).
- Не делать повторный рерайт уникальных текстов. Не добавлять контент «от себя».
- Если в документе встречаются ссылки на иные домены, **не оставлять их кликабельными**: сохранить осмысленный текст, зафиксировав изменение в отчёте.
- Не выдумывать условия бонусов, лицензий, платёжных методов, ограничений и юридические утверждения. Проверить наличие на итоговых страницах необходимых предупреждений и обязательных сведений для целевого рынка; спорные пункты вынести на согласование.

## 6. SEO и локализация

- Главный домен: `https://1-win.co.tz/`.
- HTML: `<html lang="en-TZ">`.
- Для каждой страницы использовать **собственный абсолютный URL** в `canonical` и `hreflang="en-TZ"` (например, для `/casino/`: `https://1-win.co.tz/casino/`).
- Не оставлять альтернативные языковые версии, если они не существуют.
- Создать уникальные `title`, `meta name="description"`, `h1` **на основе предоставленных текстов**. Если нужных формулировок в документах нет, использовать нейтральные значения с пометкой в `REPORT.md`, а не выдумывать предложения.
- Настроить Open Graph URL/title/description там, где применимо.
- Создать `sitemap.xml` ровно для трёх страниц и корректный `robots.txt`.
- Внутренние ссылки должны вести на целевой домен/локальные маршруты, без 404 и циклических редиректов.
- Не оставлять ссылок на старый домен, в том числе в `canonical`, `hreflang`, structured data и meta.
- Проставить один основной `h1` на страницу, логичную иерархию заголовков и `alt` для значимых изображений.

## 7. Визуальная и функциональная проверка

Провести проверку на размерах экранов примерно **1440px (desktop), 768px (tablet), 390px (mobile)**:

- Визуальная схожесть с оригинальным шаблоном для сохранённых дизайн-элементов.
- Нет горизонтального скролла из-за ошибок вёрстки.
- Не сломаны шапка, меню, футер, таблицы, карточки, изображения, раскрывающиеся блоки и кнопка копирования промокода (если присутствует).
- CSS/JS/изображения/шрифты грузятся локально или из явно разрешённых источников без ошибок 404.
- В консоли нет критических JavaScript-ошибок.
- Три страницы доступны напрямую по URL и после обновления страницы.
- Остальные страницы в `dist/` отсутствуют; навигация на них отсутствует.
- На сайте нет языковых переключателей, внешних кликабельных ссылок и старых промокодов.
- `GOL5` отображается корректно и копируется при наличии соответствующего функционала.
- Канонические адреса и `hreflang` соответствуют маршрутам.

Автоматизировать часть проверок в `validate.ts`; где полезно, добавить Playwright smoke-тесты и скриншоты в отчёт. Не объявлять проверки пройденными, если они не запускались.

Задание считается выполненным, если:

1. Сохранена отдельная полная **неизменённая** копия исходного шаблона, упакованная в ZIP.

4. Не осталось языковых переключателей, внешних ссылок и ссылок на исключённые страницы.
5. Все промокоды сайта заменены на `GOL5`; функционал копирования работает, если он был в шаблоне.
6. SEO настроено для `https://1-win.co.tz/` и `en-TZ` с корректным URL каждой страницы.
7. Нет битых внутренних ссылок и критических ошибок ресурсов/JS.
8. Десктопная и мобильная версии проверены; основные элементы дизайна сохранены.
9. Скрипты воспроизводимы, команды описаны в `README.md`.
10. Подготовлены `original-template.zip`, `finished-site.zip` и `REPORT.md`.
